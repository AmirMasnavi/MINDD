\chapter*{Abstract}
In this first task we studied 441,077 electric-vehicle charging sessions. The goal of the project is to predict,
when a session starts, whether it will end abnormally. The file has no target column, so we built it from the
end cause: the 13 causes that are faults count as abnormal, which gives 18.58\% abnormal sessions. We checked
this definition against the dataset's own history columns, and they match in about 100\% of the rows.

Several columns are only known after the session ends (energy, costs, end and payment times, end cause), so
we removed them from the predictors, together with the order creation time. We found no duplicates or invalid
records. The missing values have a clear reason and the extreme values are real, so we did not remove any
row. Volume, abnormal share and type of fault change over the two years, so we split the data by time and
not at random.

We keep 29 features in 7 groups. The recent failure history of the charging post was the strongest signal we
found.

In the second task we fixed how a solution will be evaluated, before training any model. A prediction is a risk
alert raised when the session starts. The abnormal class is the minority and a missed failure costs more than a
false alert, so the primary metric is the area under the precision--recall curve (PR-AUC), always read together
with the abnormal share of the period. Models will be compared on four expanding-window folds, one per quarter,
and the last quarter of 2021 stays untouched as the final test. Two baselines give the reference: a no-skill
baseline, and the 7-day failure rate of the post, which already reaches a PR-AUC of 0.51 against 0.18.

In the third task we compared feature groups and trained individual and ensemble models. Charging-post history
provides the largest improvement. User history adds a smaller benefit, mainly for returning users, while the tariff
adds no measurable improvement beyond the hour. Gradient boosting on 27 features reaches a PR-AUC of 0.63, above
the 7-day failure rate in every validation quarter. With alerts on 5\% of the sessions, 88\% of its alerts are real
failures, but it still misses about three quarters of them.

In the fourth task we tuned gradient boosting, the random forest and the decision tree on the same folds. No
tuned setting beat the Task 3 configuration by more than our tolerance, so gradient boosting stays the final
model. We fixed its cut-off so that 10\% of the sessions raise an alert, and only then scored the last quarter of
2021, which no earlier step had used. There it reaches a PR-AUC of 0.53, against 0.38 for the 7-day failure rate
and 0.18 for no skill. Both scores are lower than on the validation quarters, which suggests that recent post
failures predicted the next failure less well in that quarter.

The last chapter before the Synthesis brings the final choices together. One table compares the candidate,
baseline and final models, another describes the final model, and a reproducibility statement explains how every
result can be regenerated from the repository and the data file.

\chapter{Introduction}\label{ch:intro}

The project asks whether the information available when an \ac{EV} charging session starts can predict that the
session will end abnormally~\cite{brief}. We work with an educational version of the China EV Charging Dataset
\cite{zhang2025}: 441,077 sessions and 47 columns, from 31 Dec 2019 to 31 Dec 2021, at 92 charging posts in 13
stations and 3 districts. All the numbers in this report come from our notebooks
\nolinkurl{Task1.ipynb}, \nolinkurl{Task2.ipynb}, \nolinkurl{Task3.ipynb} and \nolinkurl{Task4.ipynb}
(seed 42). Chapters 2 to 6 follow the four tasks, Chapter~\ref{ch:final} gathers the final model and how to
reproduce it, and Chapter~\ref{ch:synthesis} answers the project question.

We followed three rules during the whole project. First, a variable can only be a predictor if it is known when the
session starts. Second, before fixing a problem in the data, we tried to understand it. Third, any value learned
from the data (for example, the mean used for scaling) is learned from the training period only, which is how the
data-preparation slides prevent leakage~\cite{mindd03}.

\section{Target definition}\label{sec:target}

The brief describes the target \col{is_Abnormal}, but the file does not include it. It only has \col{end_cause},
with 15 values. We decided that a session is \emph{normal} when it ends with ``Charging ends normally'' or ``User
stops charging'', because stopping is the user's own choice. The other 13 causes are equipment, communication or
vehicle faults, so we label them \emph{abnormal}.

To check this choice, we used the history columns of the dataset. For each session, they count how many earlier
sessions of the same post or user were abnormal. We recounted them with our label and with an alternative where
only ``Charging ends normally'' is normal. Our definition reproduces the supplied counts almost exactly and the
alternative does not (Table~\ref{tab:target}), so the dataset was built with the same definition as ours.

\begin{table}[!htb]
  \centering\small
  \caption{Candidate target definitions and agreement with the supplied history columns}
  \label{tab:target}
  \begin{tabularx}{\textwidth}{Lrrr}
    \toprule
    Definition of ``normal'' & Post, 30 days & User, 30 days & Abnormal share \\
    \midrule
    A: ends normally + user stops & 100.00\% & 99.98\% & 18.58\% \\
    B: ends normally only & 0.26\% & 35.85\% & 53.93\% \\
    \bottomrule
  \end{tabularx}
\end{table}

With this definition there is about 1 abnormal session for every 4.4 normal ones. A model that always predicts
``normal'' would already be 81\% accurate, so accuracy alone is not a good metric here~\cite{mindd04}. We also noticed two
details. The supplied rates are smoothed as (abnormal\,+\,1)\,/\,(sessions\,+\,5), so a post or user with no
history always gets the rate 0.2. In addition, 9,058 normal sessions (2.5\%) delivered no energy, mostly users
who stopped after about one minute. We kept them as normal, because removing them would require the energy, which
is only known after the session.

\chapter{Data Audit and Exploration}\label{ch:audit}

\section{Availability at prediction time}\label{sec:leakage}

Seven columns describe what happened during the session: energy, electricity cost, service charge, amount,
actual payment, end time and payment time. \col{end_cause} is the outcome itself. Figure~\ref{fig:auc} shows why
these columns are a problem. On its own, the energy, each money column and the duration separate normal and
abnormal sessions with an \ac{ROC-AUC} of 0.82--0.85, better than any variable known at the start (best 0.77). The
payment delay is weaker (0.61), but it is also only known after the session. The reason is that abnormal sessions
are short and deliver little energy, so these columns describe the result instead of predicting it. They are the
``information leakers'' that the data-preparation slides warn about~\cite{mindd03}, so all of them were excluded.

\begin{figure}[!htb]
  \centering

  \caption[Univariate ROC-AUC on the training period, coloured by availability at the start]{Univariate \acs{ROC-AUC} on the training period, coloured by availability at the start}
  \label{fig:auc}

The order creation time was a harder case. It is stamped after the start in 56\% of the sessions (57.2\% in the
training period, sometimes 16\,h later), so we cannot be sure it exists when we make the prediction. Its link to
the outcome is also weak (\acs{AUC} 0.59), so we excluded it too. Weather has only one value per district and day.
Following the brief~\cite{brief}, we treat it as a forecast that is known at the start.

\section{What relates to abnormal termination}\label{sec:relations}

We measured these relationships on the training period only, so that the validation and test periods do not
influence our choices. Location matters, but mostly at the level of the post. The abnormal share is 14.6--24.1\% per district and about
8--38\% per station, while the posts range from 4.1\% to 60.9\%. The 10 worst posts produce 24.1\% of the
abnormal sessions with only 10.2\% of all sessions. Calendar and weather effects are small. Across the hours of
the day the abnormal share moves between 14.7\% and 20.5\%, across the days of the week between 17.0\% and
18.9\%, and the weather effects are weak and not linear.

The history columns gave the clearest signal (Figure~\ref{fig:history}). When we split the 7-day post rate into
deciles, the abnormal share goes from about 4\% in the lowest decile to about 60\% in the highest, so a post that
failed recently tends to fail again. User history also helps, but less: its \acs{AUC} is around
0.69--0.70, against 0.75--0.77 for post history.

\begin{figure}[!htb]
  \centering
  \includegraphics[width=0.72\textwidth]{09_4_history_deciles.png}
  \caption{Abnormal share by decile of six history variables (dashed line: training average)}
  \label{fig:history}
\end{figure}

The users are very unequal. In the training period, 45\% of the 34,294 accounts have only one session, but the
top 1\% of accounts have 34\% of the sessions. New users (12\% of the sessions) fail a little more often than
returning users (20.2\% against 17.5\%).

\section{Changes over time}\label{sec:temporal}

Figure~\ref{fig:monthly} shows that the data are not stable over the two years. Monthly volume drops to 1,391
sessions in February 2020, probably because of COVID-19, and reaches 25--28k sessions per month in autumn 2021.
The abnormal share falls from 26.3\% to 13.7\% and later rises again to 22.9\%. The type of fault also changes:
connection faults add 7.1 percentage points to the abnormal share in Q1-2020, but only 1--2 points from Q3-2020
onwards. At the start of the file the history columns are still incomplete, which is why 31\% of the sessions in
January 2020 come from ``new'' users, against about 9--15\% later. Finally, posts 17--20 stop on 28 Sep 2021.
Some things are stable, though. The abnormal share of each post is similar in 2020 and 2021 (Spearman 0.81),
which explains why post history works. Because of all the changes above, a random split would mix different
periods and give results that are too optimistic, so we split the data by time, as is usual for data that are
ordered in time~\cite{fpp3}.

\chapter{Preparation}\label{ch:prep}

\section{Chronological split}\label{sec:split}

We did not use the sessions before 1 April 2020 (the \emph{burn-in}), because their history columns are
incomplete and their fault mix no longer exists. The remaining data were split by start date into training,
validation and test periods (Table~\ref{tab:split}). The label of a session is only known when it ends, so we
also removed (\emph{purged}) the 28 training sessions that end after the training cut-off. Otherwise their labels,
which only exist after the cut-off, would leak into training~\cite{mindd03}.

    Period & Dates & Sessions & Abnormal \\
    \midrule

The split shows two things that matter for the evaluation. First, 39.9\% of the validation sessions and 61.3\% of the
test sessions come from accounts that never appear in training, so \col{user_id} cannot be a feature. Second,
every post in validation and test was already seen in training, so we cannot test a brand-new post. The training
and validation periods together form the development data. Chapter~\ref{ch:eval} divides them into four
expanding-window folds, and the validation quarter of Table~\ref{tab:split} is the fourth one, so we do not use a
random K-fold.

We keep 29 features in 7 groups: calendar (hour and day of week), tariff period, location (\col{post_id},
station and district), weather (temperature, humidity, precipitation and a new \col{rain_flag}), post history
(8), user history (10) and concurrency (1). Table~\ref{tab:dropped} lists the start-time columns we dropped.

Some features are strongly related to each other. Only the user-history windows have a \ac{VIF} above 10 (up to
65.4)~\cite{mindd03}, because the 180-day and 730-day windows contain almost the same sessions. Tree models and regularised
linear models can deal with this, so they get all the features. For plain linear or distance-based models we
built a smaller set. We went through the features from the best to the worst univariate \acs{AUC} and kept a feature
only if its $|\rho|$ with the features already kept was below 0.90. This leaves 19 of the 23 numeric features and
brings the maximum \acs{VIF} down to 8.6.

\ac{PCA}~\cite{mindd03} was also tested. It needs 11 of the 23 components to keep 90\% of the variance, and the first component hardly
separates the classes (\acs{AUC} 0.51). Since it compresses little and would mix post and user information, we did not
use it. Discretisation~\cite{mindd03} was only used to explore the data (deciles and weather bands), not as a model input.

\section{Learned operations and class imbalance}\label{sec:prep}

Different models need different preparation, so we prepared two versions of the data. The tree version keeps the
raw values, the \acs{NaN} and the category codes. The linear version applies \texttt{log1p} to 8 skewed columns, fills
the structural \acs{NaN} with the training maximum (we read ``never happened'' as ``a very long time ago'') and keeps
the flags. It then standardises the numeric columns, encodes hour and weekday with sine and cosine (the cyclical
encoding recommended for circular variables), and one-hot encodes \col{post_id} and the tariff period~\cite{mindd03}. The result has 126 columns and no \acs{NaN}.

All operations that learn something are fitted on the training period only, inside a scikit-learn
pipeline~\cite{sklearn,pedregosa2011} (Table~\ref{tab:ledger}). We checked what would happen if we fitted them on all periods instead, and the learned
values change. For example, the fill value for ``days since the user's last failure'' would move from 543 to 702
days, which would leak information from the validation and test periods.

\begin{table}[!htb]
  \centering\small
  \caption{Learned operations, all fitted on the training period}
  \label{tab:ledger}
  \begin{tabularx}{\textwidth}{LLL}
    \toprule
    Operation & What is learned & Applies to \\
    \midrule
    One-hot encoding / category codes & List of categories & Linear / tree version \\
    Structural-\acs{NaN} fill & Training maximum (flags kept) & Linear version \\
    Standardisation & Mean and standard deviation & Linear version \\
    Log-transform rule & Which columns are skewed & Linear version (8 columns) \\

    \bottomrule
  \end{tabularx}

The classes (about 1\,:\,4.4) are not balanced in the prepared data. Any class weights or resampling would be
applied only inside the training folds, so that validation and test keep their real distribution. The models of
Chapter~\ref{ch:models} use neither and are judged with ranking and probability metrics. We avoided
\ac{SMOTE}~\cite{mindd03}, because interpolating between sessions can create values that cannot exist, such as half a flag or a mix of two
posts.

\chapter{Prediction and Evaluation Setting}\label{ch:eval}

In the second task we fixed what exactly is predicted and how a solution will be judged, before training any
model. The notebook \nolinkurl{Task2.ipynb} fits no model. It builds the evaluation protocol and checks it with
two simple baselines.

\section{Prediction problem}\label{sec:problem}

The unit of observation is one charging session, that is, one transaction of one account at one charging post.
The positive class is an abnormal ending (\col{is_Abnormal}\,=\,1, one of the 13 fault causes). The negative
class is a normal ending or a stop requested by the user, as defined in Section~\ref{sec:target}. In the
development period (April 2020 to September 2021), 18.5\% of the 346,979 sessions are abnormal.

The prediction is made once, at the start of the session, with only the information known at that moment. We
designed it for preventive monitoring and maintenance prioritisation. The sessions that are starting, and through
them the posts, are ranked by their risk of failure, so that an operator with limited capacity looks first at the
riskiest ones. Predicting a session as abnormal is therefore a risk alert: this session, on this post, has an
increased risk of ending in a failure. It is not a diagnosis and it does not say which fault will happen. The
positive class also mixes 13 causes whose mix changes over time (Section~\ref{sec:temporal}), so a model could
detect one type of failure well and miss another.

\section{Variables available at the start}\label{sec:variables}

We placed each of the 47 supplied columns in one of the four categories of the brief~\cite{brief}
(Table~\ref{tab:classification}). The notebook builds this table in code and checks that every column appears
exactly once.

We exclude the seven after-session columns and \col{end_cause} because a model that used them could not run when
the session starts. \col{UserID} is excluded because 35\% to 46\% of the validation sessions of each
fold come from accounts that are not in the training window. A model would only memorise accounts, and it would
identify people. The user history is the legitimate substitute.

The eligible set depends on assumptions that the data cannot prove. Weather is taken as a forecast, as the brief
says. The history columns are taken as supplied. In production they keep updating, so in a validation period they
already contain the outcomes of earlier sessions of that period that had finished. User history needs the platform
to identify the account at the start, otherwise the user group is missing (the cold-start case). Finally,
\col{post_id} is also an identifier, but the post is known at the start and is the most informative location
level, so it stays here. The ablation of Section~\ref{sec:ablation} shows that it adds nothing once the post history is known.

\section{Consequences of the two errors}\label{sec:errors}

A \ac{FP} flags a normal session as risky, and a \ac{FN} lets an abnormal session pass unnoticed~\cite{mindd04}. What they cost
depends on the action that follows the alert. With automated monitoring, a false alert is one more line on a
dashboard, while a missed failure means that the next sessions on that post are not watched. With an inspection or
a maintenance visit, a false alert wastes technician time, while a missed failure leaves a faulty post in service.
Failures cluster by post (Figure~\ref{fig:history}), so one missed failure is usually followed by more. Warning the
driver is the most delicate action, because false warnings make drivers stop trusting the alerts, so we left it
out of the main use.

For a single event, we consider the false negative the more expensive error, because the action after an alert is
cheap compared with a failure that continues unseen. However, the number of false alerts is limited by the
capacity of the operators, and a very long list of alerts becomes useless. The application therefore needs a good
ranking, with the real failures near the top, and a fixed number of alerts that the team can handle.

We do not know the cost ratio $c = \text{cost(FN)}/\text{cost(FP)}$. With calibrated probabilities the best
cut-off would be $t^{*} = 1/(1+c)$, which gives 0.50 for $c=1$, 0.33 for $c=2$ and 0.17 for $c=5$. For $c$ above
4.4 the cut-off is below the abnormal share and almost every session would be flagged. Fixing a cut-off now would
be arbitrary. Instead, we chose metrics that judge the ranking and the quality of the probabilities, and we report
the operational results for fixed alert budgets (5\%, 10\% and 20\% of the sessions flagged). The cut-off will be
chosen later, from the cost ratio and the capacity, as in the threshold exercise of the evaluation
lab~\cite{mindd_lab_eval}.

    \midrule
    \acs{PR-AUC} (primary) & The abnormal class is the minority and both errors matter. It measures how precise the alerts stay as more failures are caught, and it ignores true negatives~\cite{mindd04,saito2015} & Its no-skill value is the abnormal share, which changes between periods, so we read it next to that share and as a lift \\
    \addlinespace[2pt]
    \acs{ROC-AUC} (complementary) & The chance that an abnormal session is ranked above a normal one. It does not depend on the abnormal share, so it can be compared across periods & Can look optimistic with imbalanced classes~\cite{saito2015} and says little about the top of the ranking \\
    \addlinespace[2pt]
    Brier score and log-loss (complementary) & They measure the quality of the probabilities~\cite{brier1950,sklearn}, which a cost-based cut-off needs & Only for models that output probabilities; both depend on the abnormal share \\
    \addlinespace[2pt]
    Precision, recall and correct, false and missed alerts per 1,000 sessions, at an alert budget (operational) & The budget is the practical limit and is the same for every model and period, and the counts turn the errors into workload & The budgets are assumptions, because the real capacity is unknown; the counts depend on the abnormal share of the period \\
    \addlinespace[2pt]
    Value per fold, standard deviation, worst fold, trend, folds won (stability) & A model should not be judged by its average only & Four folds give only a rough idea of the variability \\
    \bottomrule
  \end{tabularx}
\end{table}

We do not use accuracy, which gives the same importance to both classes~\cite{mindd04}. Always predicting
``normal'' is right in 79--84\% of the sessions of each fold and catches no failure. F1 and similar metrics need a cut-off that is not chosen yet, and F1 gives the same weight to both
errors, so they can only be reported once the final cut-off exists.

\section{Temporal evaluation}\label{sec:folds}

The sessions cannot be divided at random, because volume, abnormal share and fault mix change over time
(Section~\ref{sec:temporal}) and a model is always used on future sessions. Training sessions must come before
the sessions that evaluate them, as in the time-series cross-validation of forecasting
practice~\cite{fpp3}. We keep the burn-in and the test period of Section~\ref{sec:split} and divide the
development period into four expanding-window folds (Table~\ref{tab:folds} and Figure~\ref{fig:folds}). Each fold
trains on the sessions that started and ended before its validation quarter. The fourth fold is exactly the
training and validation periods of Table~\ref{tab:split}.

The boundaries are calendar quarters, fixed before looking at any model result. A quarter is about one season. It
is large enough for a stable estimate (every validation quarter has at least 6,600 abnormal sessions) and short
enough to show changes over time. Four folds are a compromise: an earlier fold would train on less than six months
of data, and monthly folds would give 12 small and noisy estimates. The window is expanding because the model that
would be deployed is trained on all the past.

The folds are not equal. The validation quarters have between 41,797 and 75,769 sessions, and the training window
grows from 6 to 15 months, so the first folds train on less data and do not include a full winter. We expect their
scores to be a little pessimistic. The label of a session is only known when it ends, so the 27 to 39 training
sessions per fold that were still running at the boundary are purged.

Every operation that learns from the data (Table~\ref{tab:ledger}) is fitted again inside each training fold,
together with the model, and applied unchanged to the validation quarter. Class weights or resampling, if used,
change the training rows only. Even a simple statistic differs between folds: the class prior goes from 17.7\% to
18.9\%, and no fold has the 18.5\% of the whole development period. The difference is small here, but it would be
larger for steps that use the target.

To protect the test period, we follow the golden rule of the evaluation slides: data used to evaluate a model
cannot be used during its development~\cite{mindd04}. The Task 2 notebook counts its 80,081 sessions and removes them right after reading
the file. Model, hyperparameters and cut-off will be chosen with the four folds only. The
cut-off will be chosen on the out-of-fold predictions of the four folds together and then frozen, as in the
evaluation lab of the course~\cite{mindd_lab_eval}. The final model
will be refitted on the whole development period and scored once on the test.

\section{Aggregation across folds}\label{sec:aggregation}

We rank the models by the unweighted mean of the \ac{PR-AUC} of the four folds. We want a model that works in a
future period, so each period counts once. Next to it we report the mean weighted by the number of validation
sessions, which reflects the operational volume, and the pooled value over all out-of-fold predictions, which is
needed to choose the cut-off but is dominated by the large folds. Stability is described by the value in each
fold, the standard deviation, the worst fold and the trend. An improving trend is partly expected, because later
folds train on more months, while a falling trend would be a sign of drift.

The abnormal share differs between folds, so the scores of two folds cannot be compared directly, but the
difference between two models on the same fold can. We therefore compare models fold by fold, with the paired
differences and the number of folds won. The evaluation slides compare models with a Wilcoxon test on the
folds~\cite{mindd04}, but with four folds the smallest possible $p$-value of an exact Wilcoxon test is 0.125, even when a model wins in every fold, so we do not claim statistical significance for these
comparisons. When two models are within about one standard deviation of each other, we will prefer the simpler and
more stable one.

\section{Feature-group ablation}\label{sec:ablation}

We compared the four nested feature sets of the brief with one fixed reference model: gradient boosting with depth
6, learning rate 0.1, 200 iterations and at least 100 sessions per leaf, which we did not tune. With the same
untuned model for every set, the differences come from the information and not from tuning, and the model handles
categories, missing values and interactions without extra preparation~\cite{sklearn}. We judge each step by its paired
difference in \acs{PR-AUC}, fold by fold, and treat differences below 0.005 as practically negligible. A
bootstrap of each validation quarter (100 resamples of the sessions, the resampling of the evaluation slides~\cite{mindd04}) gives
a standard error of 0.004 to 0.006 for one model's \acs{PR-AUC}. This gives a rough scale for the tolerance, not a
test of a paired difference. Sessions share posts, users and periods, so the independent-session resampling can
understate uncertainty.

Table~\ref{tab:ablation} and Figure~\ref{fig:ablation} answer the questions of the brief. The tariff gives no
measurable improvement beyond the time of day in these experiments. Adding it changes the mean \acs{PR-AUC} by
$+0.0006$, and its fold differences ($-0.0033$ to $+0.0038$) stay inside the practical tolerance. The tariff period
is a deterministic function of the start hour, so a model that already has the hour can rebuild it. Charging-post
history provides by far the largest improvement. It raises the mean \acs{PR-AUC} from 0.290 to 0.584, with a large
gain in every quarter ($+0.249$ to $+0.360$). With it, the model is above B1 in every fold, by $+0.061$ to
$+0.090$, so it does more than repeat the 7-day failure rate. User history adds a smaller benefit, $+0.031$, which
is positive in every fold but falls from $+0.044$ in fold 1 to $+0.018$ in fold 4. The ordering of the sets is the
same in every fold, but the size of the gains varies: the post-history gain differs by 0.11 between quarters and
the user-history gain shrinks.

The benefit of user history is much larger for returning users: pooled \acs{PR-AUC} rises from 0.609 to 0.640
($+0.032$). About 13\% of the validation sessions come from new accounts. For them the change is smaller and
mixed: \acs{PR-AUC} rises from 0.513 to 0.519 ($+0.0057$), just above our practical tolerance, while
\acs{ROC-AUC} falls from 0.730 to 0.727. A new account has no completed history, but its indicators and concurrency
variables can still carry information, and fitting a model with another feature group changes predictions for all
sessions. These results do not establish that user history cannot help a new account.

We then removed two variables from S4. Without \col{post_id} the mean \acs{PR-AUC} rises by $+0.0107$, in all
four folds. In these folds its identity adds no predictive benefit once the history is known. Removing it also
reduces the opportunity to memorise devices whose failure patterns change over time. Removing the tariff as well
changes the result by $+0.0003$, inside the tolerance, so it goes too. The selected set has 27 features and a mean
\acs{PR-AUC} of 0.626. Without the 11 user variables the mean result falls by 0.027 to 0.599, with a loss in every
fold ($-0.017$ to $-0.037$), so by our rule user history stays. We add no new feature. The start-time columns were
chosen in Task~1, post history provides the largest measured improvement, and a new history feature would need its
own check that every session it counts had ended before the start.

Some groups raise operational or ethical concerns, the kind of risk that the introductory slides list for data
mining~\cite{mindd01}. The post history needs a live record of finished sessions,
which always lags, because a label only exists when a session ends, up to 24\,h later. If alerts lead to
maintenance, failures may fall and the history may change, so the model can also reflect the maintenance policy.
Station and district identify infrastructure rather than an account, although linkage with other records can still
raise privacy concerns. The abnormal share goes from about 8\% to 38\% between stations, so the distribution of
alerts should be monitored per station. User history is a behaviour profile tied to a persistent account. Its use
therefore needs a clear purpose and data-minimisation safeguards~\cite{gdpr}. A driver who used a faulty post could
receive a higher score, so the user could be blamed for a failure of the infrastructure. We keep it
because it improves the ranking, but only for an internal ranking of sessions and never for a decision about a
driver. The set without user history (0.599) is the fallback.

\section{Individual models}\label{sec:individual}

The brief lists five modelling principles and asks for at least three~\cite{brief}. We chose a linear, a probabilistic
and a tree-based classifier from the families of the predictive-models slides~\cite{mindd05}
(Table~\ref{tab:individual}). The 27
features mix two categories, two circular calendar variables, weather, skewed counts and times, bounded rates and
four variables with structural missing values. About 18.5\% of the sessions are abnormal. In Task~1 we decided not
to resample, so every model learns the natural class prior.

We left out two principles. k-nearest neighbours keeps every training session and needs a distance on inputs of
the same scale, which is hard with counts, rates and categories together, and each of the 42,000 to 76,000
validation sessions of a fold would be compared with up to 271,000 training sessions. A kernel \acs{SVM} needs a
time between quadratic and cubic in the number of training sessions and returns a distance from the hyperplane
rather than a probability~\cite{mindd04,mindd05}. Both would need a subsample, which would throw away the history that carries the signal.

Each model gets the preparation that the slides recommend for it~\cite{mindd05}. The logistic regression uses the linear version
of Task~1: training maximum for the structural \acs{NaN}, \texttt{log1p} for a fixed list of non-negative
counts, gaps and precipitation, standardisation,
one-hot station and district, and sine and cosine of hour and weekday, the cyclical encoding of the
data-preparation slides~\cite{mindd03}. The log-transform list is fixed from the meaning of the variables, rather
than selected again using later periods. Naive Bayes keeps all eligible numeric inputs and cuts continuous ones into
10 equal-frequency bins learned on each training fold~\cite{mindd03,sklearn}. Its category encoder reserves code
zero for unseen categories, and Laplace smoothing uses $\alpha=1$. We do not reuse the target-based reduced
feature list learned in Task~1. The trees use the category codes of Task~1. The slides
advise against imposing an arbitrary order on unordered categories, and we keep the codes for a reason: after
\col{post_id} is dropped only 13 stations and 3 districts remain, and a tree can isolate any single code with two
splits, so the order blocks no partition that it needs. Gradient boosting reads the same codes as categories, so for
it no order is imposed at all.

The first version of our notebook also capped the logged columns and the number of active sessions at the 0.1\%
and 99.9\% training quantiles, which contradicts the Task~1 decision not to cap outliers. We tested both. With the
caps the mean \acs{PR-AUC} of the logistic regression changes by $-0.0001$ (0.5925 against 0.5924), and no fold moves
by more than 0.0002. With 111,000 to 271,000 training sessions per fold, the extreme 0.1\% are only a few hundred
sessions. Their effect on predictive performance is negligible in this comparison. We kept the Task~1 preparation.

We tuned only the setting that controls the complexity of each model and kept the simplest configuration within
the tolerance of the best one. For logistic regression, $C=0.01$ and $C=1$ give similar mean \acs{PR-AUC}
(0.5925 and 0.5923), with small differences in every fold, so we kept the stronger penalty. For the tree, depths 4 and 6 underfit
(0.540 and 0.582), and depths 8 and 12 are tied (0.597 and 0.599), with a worse log-loss at depth 12 (0.354
against 0.347), so we kept depth 8. For Naive Bayes we keep 10 bins and Laplace smoothing fixed. It ranks sessions reasonably (\acs{ROC-AUC}
0.814) but its \acs{PR-AUC} is only 0.525, and its probabilities are worse than the constant prior (Brier score 0.172
against 0.148, log-loss 0.839 against 0.472). This is consistent with overconfidence when the conditional-independence assumption~\cite{mindd05} fails:
the overlapping windows describe some of the same failures. The tree and the logistic regression reach
almost the same result (0.597 and 0.593), both 0.08 to 0.09 above B1, although one is linear and the other is
not. This suggests that the available information strongly limits both models.

\section{Ensemble models}\label{sec:ensembles}

We chose one ensemble for each of three ideas: lowering the variance of a model (bagging), lowering its bias
(boosting) and combining models with different inductive biases (stacking). The predictive-models slides do not
cover ensembles~\cite{mindd05}, so we explain each one with ideas that they do cover.

\begin{itemize}
  \item The random forest~\cite{breiman2001} averages 200 trees, each fitted on a bootstrap sample~\cite{mindd04} and
  with a random subset of features at each split. A single tree is unstable~\cite{mindd05}, and averaging trees fitted on different samples cancels much of that
  noise while keeping the low bias of a deep tree.
  \item Gradient boosting~\cite{friedman2001,sklearn} adds shallow trees one after another, each fitted to the remaining errors of the previous
  ones. A shallow tree can underfit, and the sequence can lower that bias step by step. We explicitly disable
  internal early stopping and compare fixed iteration counts, so that no random internal validation split is used.
  \item The stacking~\cite{wolpert1992} combines the logistic regression, Naive Bayes and the tree with a logistic regression on their
  predictions. The three make different errors, and the meta-model learns how much to trust each. We did not use
  equal-weight voting, because one constituent is much weaker; stacking can learn a different contribution for each.
\end{itemize}

The random forest keeps the smaller leaf size (50 sessions, 0.622 against 0.616 with 200, better in all four folds).
Gradient boosting keeps depth 6 with learning rate 0.1 and 200 iterations (0.626). Depth 3 is lower (0.621), and
the slower setting with 300 iterations is tied with it.

The brief warns that the predictions that train the meta-model of a stacking must not leak~\cite{brief}, and that a random
inner cross-validation lets later sessions shape the predictions for earlier ones. We built them in time order
(Figure~\ref{fig:stacking}). The training window of each fold is cut into quarters. For every quarter after the
first, the base models are fitted on the sessions that started and ended before it and predict it. The meta-model
learns from these predictions, the base models are refitted on the whole window, and the meta-model combines their
predictions for the validation quarter. Sessions whose label is not yet known at the start of the validation
quarter are removed, as in the purge of Task~2, and assertions in the code check the timing of every inner fit.
The feature set and base-model configurations were selected using the development folds; these checks concern
how the meta-training predictions are constructed, not an independent estimate of the full selection procedure.
The coefficient on the Naive Bayes logit moves from 0.023 in fold 1 to $-0.001$ in fold 4, while logistic
regression has coefficients from 0.56 to 0.66 and the tree from 0.31 to 0.47. These are coefficients on correlated
logit scores, not percentages of a weighted average. Their pattern suggests little additional contribution from
Naive Bayes once the other two predictions are known.

  \centering
  \includegraphics[width=0.9\textwidth]{05_3_stacking_design.png}
  \caption[Stacking without leakage]{Stacking without leakage: the out-of-fold predictions that train the
  meta-model are built in time order inside the training window (outer fold 4)}
  \label{fig:stacking}

All three ensembles improve on their constituents in every fold. The random forest is $+0.025$ above the tree and
gradient boosting $+0.028$, consistent with the benefits of averaging and sequential correction. Their tree settings also differ from the
single CART model, so this comparison does not isolate variance and bias separately.
The stacking is above the logistic regression by $+0.018$, the tree by $+0.013$ and Naive Bayes by $+0.085$, but its
gain over the best constituent is the smallest of the three, and in practice it mixes the linear model and the
tree. Gradient boosting and the random forest are within the practical tolerance ($+0.0034$ for boosting,
ahead in three folds).

\chapter{Optimisation, Threshold and Final Evaluation}\label{ch:optim}

In the fourth task we tuned the most promising models, chose the final model and its cut-off, and only then scored
the test period~\cite{brief}. Every choice up to Section~\ref{sec:optim-test} uses the four development folds of
Chapter~\ref{ch:eval}. The model, the 27 features and the cut-off were written to file before the test rows were
read, and the test period was scored once, with nothing changed afterwards.

\section{Models chosen and search}\label{sec:optim-search}

We optimised gradient boosting, the random forest and the decision tree. They are the two best ensembles and the
best individual model of Table~\ref{tab:comparison}, and they cover three principles: boosting, bagging with random
feature subsets, and a single tree. Gradient boosting and the forest were only 0.003 apart, inside our tolerance,
so both needed a search before we named the final model. The tree's two complexity controls, depth and minimum leaf
size, are the settings the predictive-models slides say to choose on validation data~\cite{mindd05}. We left out
stacking, which is 0.015 behind and would need three base models and a meta-model tuned in the inner loop; logistic
regression, whose two penalties already gave the same \acs{PR-AUC} in every fold; and Naive Bayes, whose only
setting does not touch the independence assumption behind its gap.

Each model was searched on an explicit grid (Table~\ref{tab:optim-grid}). Every configuration was fitted on the
training window of each fold and scored on the quarter that follows, so the search respects time order and never
sees the test period. The objective is the unweighted mean \acs{PR-AUC} of the four folds. We used the selection
rule of Task 3: among the configurations within 0.005 of the best mean, keep the simplest. When the choice sat on
the edge of a range, we widened that range once. Grid search is not in the slides; we used it because it states
the search space and the procedure exactly, which the brief asks us to report, and with at most 41 configurations
per model a random search would not cover the space better~\cite{sklearn}.

\section{Decision threshold}\label{sec:optim-threshold}

A score becomes an alert only once a cut-off is fixed. Of the criteria in the brief, we used the operational
alert-rate constraint of the protocol: the cut-off flags 10\% of the sessions, so an operator inspects about 100
sessions in every 1,000. We have no data on the cost of a missed failure against an unnecessary inspection, so a
cost function would need an invented ratio, and the protocol does not select with F1 because it weights
precision and recall equally without an operational reason. A minimum recall would leave the workload open. An
alert budget is the one quantity an operator can set directly, and 10\% is the middle of the three budgets of the
protocol~\cite{mindd_lab_eval}.

The cut-off was computed on the pooled out-of-fold predictions: each of the 235,472 validation sessions was scored
by the final configuration fitted on its own fold's training window. The 90th percentile of these scores is 0.490.
Applied to each fold, it flags 7.7\% to 12.2\% of the sessions, following the abnormal share of the quarter, while
precision stays between 0.713 and 0.751. A fixed cut-off keeps the quality of an alert stable, and the number of
alerts rises and falls with the failure level.

Table~\ref{tab:optim-cutoff} compares the two cut-offs. On development they are almost the same: the selected
cut-off adds 1.3 correct and 1.4 false alerts per 1,000 sessions. This is not a property of 0.50. It happens
because the scores of this model are close to probabilities (Section~\ref{sec:optim-calibration}) and about 10\% of
the sessions have a predicted risk above one half. Figure~\ref{fig:optim-threshold} shows that F1 would peak near a
cut-off of 0.3, where the model flags well over 10\% of the sessions. Our cut-off comes from a stated capacity, so
it would stay meaningful for a model whose scores are not calibrated.

For an operator, the 10\% budget means 74.0 real failures and 26.0 false alerts in every 100 inspections per 1,000
sessions, while 109.8 of the 183.8 abnormal sessions per 1,000 are still missed. The protocol's other budgets show
the trade-off: going from 5\% to 10\% adds 29.3 correct alerts for 20.7 false ones, while going from 10\% to 20\%
adds 34.4 correct alerts for 65.6 false ones. Of the three budgets, 10\% is the last one where the extra alerts are
more often right than wrong. Read as a probability, the cut-off of 0.490 treats a missed failure as costing about
the same as an unnecessary inspection (a cost ratio of 1.04), less than Section~\ref{sec:errors} argued; a larger
budget would follow if the operator has the capacity.

\section{Calibration}\label{sec:optim-calibration}

\begin{wrapfigure}{r}{0.45\textwidth}
  \centering
  \vspace{-\baselineskip}
  \includegraphics[width=0.45\textwidth]{task4_07_calibration.png}
  \caption[Reliability of the final model]{Reliability of the pooled out-of-fold scores (ten bands of equal size) and their distribution}
  \label{fig:optim-calibration}
\end{wrapfigure}

The cut-off uses the scores only as a ranking, but an operator may read them as risks, so we checked whether they
behave as probabilities. Trees and boosted trees can give scores that are not probabilities~\cite{mindd04,niculescu2005}.
On the pooled out-of-fold predictions, the Brier score~\cite{brier1950} is 0.103, against 0.150 for a constant
prediction of the training prior. In ten bands of equal size (Figure~\ref{fig:optim-calibration}), the mean
predicted score and the observed abnormal share differ by at most 0.015. The model slightly under-predicts in the
middle bands and is accurate in the top band, where the alerts are (0.738 predicted, 0.740 observed).

We did not add a calibration step. A calibration that keeps the order of the scores flags exactly the same 10\% of
the sessions, and the largest gap, under two percentage points, is small enough to read the scores as approximate
risks.

\section{What drives the final model}\label{sec:optim-importance}

We measured how much the final model uses each group of information with permutation importance: on each
validation quarter, the columns of one group are shuffled together across the sessions and the drop in
\acs{PR-AUC} is recorded, five times per group, with the configuration fitted on that fold's training
window~\cite{breiman2001,sklearn}. Permutation importance is not in the slides; we used it because it works for any
model and is measured on sessions the model did not see. Shuffling a group at once keeps its correlated history
windows from standing in for each other.

\begin{figure}[!htb]
  \centering
  \includegraphics[width=\textwidth]{task4_10_importance.png}
  \caption[Permutation importance of the final model]{Permutation importance of the final model on the four validation quarters: (a) feature groups (bar: range over the folds); (b) the ten leading variables (bar: standard deviation)}
  \label{fig:optim-importance}
\end{figure}

The post history dominates (Figure~\ref{fig:optim-importance}). Shuffling its eight variables lowers the
\acs{PR-AUC} by 0.366 on average. User history comes second (0.097), and
its role shrinks over time, from 0.108 in fold 1 to 0.067 in fold 4. Location costs 0.012; calendar, concurrency
and weather less than 0.002 each, so the model barely uses them. The leading single variable is the post's abnormal
rate over the last day (0.196), ahead of the time since the post's last abnormal session (0.038) and the 7-day rate
that B1 uses (0.026).

The ranking agrees with the ablation of Section~\ref{sec:ablation}, but the sizes differ: removing post history and
retraining cost 0.294, and removing user history 0.027, against permutation drops of 0.366 and 0.097. The two
methods answer different questions. Permutation measures how much this fitted model uses a group; the ablation
measures what is lost when the model is retrained without it, and a retrained model can partly replace user
history with post history. The method has three limits here. Correlated variables share importance, so single
variables are understated when the other windows are left intact. It measures use, not cause. And it describes
the model on the validation quarters, before the change seen on the test period.

repeated it unchanged; its notebook prints the re-run's freeze time, and the submitted file keeps the original. No model, feature, hyperparameter or threshold was changed after the test result was seen.

\chapter{Synthesis}\label{ch:synthesis}

The project asks to what extent the information available when a charging session starts can predict that it
ends abnormally. The file has no target column, so we built it from the end cause, and the dataset's own history
columns reproduce our definition almost exactly (Table~\ref{tab:target}). The columns that separate the classes best (energy,
cost and duration, with an \acs{AUC} of 0.82--0.85) describe the result of the session, so they cannot be
predictors. The best variable known at the start reaches 0.77. It is the recent failure history of the post: the
abnormal share goes from about 4\% in the lowest decile of the 7-day rate to about 60\% in the highest. User
history comes second (0.69--0.70), and calendar and weather add little. The records needed no repair. We found no
duplicates or invalid values, the missing values only mean that there was no earlier session or failure, and the
extreme values are real situations, so no row was removed or imputed. The data change over the two years: the
abnormal share moves between 13.7\% and 26.3\%, and connection faults, which added 7.1 points in the first quarter
of 2020, add only 1--2 points from the third quarter on. For this reason the sessions are split by time, the first
three months are left out as a burn-in, and every score is read against the abnormal share of its own period.

Under this protocol, the 7-day failure rate of the post, used alone and without fitting anything, reaches a mean
\acs{PR-AUC} of 0.511 on the four validation quarters, against 0.181 for no skill. In the models of
Chapter~\ref{ch:models}, recent post history provides the largest measured contribution: it lifts the \acs{PR-AUC} from 0.290 with context, weather and tariff to 0.584.
User history adds 0.031, with a much larger benefit for returning users and mixed changes for new users. The tariff
adds no measurable improvement beyond the hour. The best model, gradient boosting on 27 features, reaches 0.626, above B1 in all four folds by 0.115 on average, and a logistic regression
already reaches 0.593, suggesting that the available information limits what these models can achieve. With alerts on 5\% of the sessions, 88\% of its alerts
are real failures, against 74\% for B1, but it still catches only a quarter of the failures. Tuning did not
improve on these settings (Chapter~\ref{ch:optim}).
On the untouched test quarter it reaches a \acs{PR-AUC} of 0.532, against 0.381 for B1
and 0.178 for no skill (Table~\ref{tab:final-comparison}). With the cut-off fixed beforehand at a 10\% development alert rate, it flags 7.4\% of the
test sessions: 50 correct alerts, 24 false alerts and 126 missed failures per 1,000. The margin over B1 holds, but both fall well below their development
level (by 0.093 and 0.130). So the information available at the start supports a useful ranking of risky
sessions, with post history providing most of the measured improvement, but the strength of that signal changes
over time. Performance on failures without recent post failures is still untested.

Weather is assumed to be a start-time forecast despite its daily resolution. Durations stop at 24\,h, and the
order and payment timestamps remain unexplained. Every validation post was seen in training, so new-post performance
is untested. User history raises privacy concerns~\cite{gdpr}; it should only support internal session rankings,
with the user-free model (0.599) available as an alternative. Feature sets, hyperparameters and the cut-off were chosen on the
reported folds, so the development scores are optimistic, the ablation covers one model family, and the test
period is a single quarter. The 0.005 tolerance is a
practical rule; session resampling ignores dependence, and four folds are insufficient for reliable significance
claims. The scores are close to calibrated, but error costs are unknown, so the 10\% budget is a choice, not a measured
capacity. B1's 7-day window came
from Task~1's ranking, whose training period overlaps folds 1 to 3; we expect a small effect because B1 fits
nothing. Finally, combining 13 fault causes can hide failure types that the model never detects.
